## Q&A (answers from the paper)

These answers come from the paper itself, not from an interview. Direct quotes are marked with their section in the [arXiv paper](https://arxiv.org/abs/2304.03442).

**Q1: Why does the architecture need all three components -- memory, reflection, and planning?**

A1 (from the paper, Section 6.5.1): The full architecture produced the most believable behavior (mu = 29.89). Each ablation reduced performance: no reflection (mu = 26.88), no reflection or planning (mu = 25.64), no memory/planning/reflection (mu = 21.21). The effect size between the full architecture and the fully ablated baseline is d = 8.16 -- "eight standard deviations." All pairwise differences were statistically significant (p < 0.001), except the crowdworker baseline vs the fully ablated condition.

**Q2: How does the memory retrieval scoring work?**

A2 (from the paper, Section 4.1): "To calculate the final retrieval score, we normalize the recency, relevance, and importance scores to the range of [0, 1] using min-max scaling. The retrieval function scores all memories as a weighted combination of the three elements: score = alpha_recency * recency + alpha_importance * importance + alpha_relevance * relevance." Recency uses an exponential decay function with factor 0.995 per game hour. Importance is an LLM-generated integer 1--10. Relevance is the cosine similarity between the query's embedding and each memory's embedding.

**Q3: When and how do agents reflect?**

A3 (from the paper, Section 4.2): "We generate reflections when the sum of the importance scores for the latest events perceived by the agents exceeds a threshold (150 in our implementation). In practice, our agents reflected roughly two or three times a day." The reflection process: (1) query the 100 most recent records, (2) prompt the LLM for "3 most salient high-level questions," (3) retrieve memories for each question, (4) prompt for "5 high-level insights" with evidence citations, (5) store insights as reflection memories.

**Q4: How does planning work, and can agents change plans?**

A4 (from the paper, Section 4.3): "Our approach starts top-down and then recursively generates more detail." The LLM first generates a broad daily agenda (5--8 chunks), which is recursively expanded into hour-level and minute-level plans. "Agents may change their plans midstream if needed." Plans are stored in the memory stream and included in retrieval, so "the agent [can] consider observations, reflections, and plans altogether when deciding how to behave."

**Q5: What emergent behaviors were observed?**

A5 (from the paper, Section 7.1.2): "During the two-day simulation, the number of agents who knew about Sam's mayoral candidacy increased from one (4%) to eight (32%), and the number of agents who knew about Isabella's party increased from one (4%) to thirteen (52%)." Network density increased from 0.167 to 0.74. "On Valentine's Day, five out of the twelve invited agents showed up at Hobbs cafe to join the party."

**Q6: What were the main failure modes?**

A6 (from the paper, Section 7.2): Three modes: (1) memory retrieval failures -- agents sometimes retrieved incomplete fragments or failed to recall events they had experienced; (2) misclassification of physical norms -- e.g., agents entered a one-person bathroom simultaneously or visited stores after closing time; (3) instruction-tuning effects -- "the dialogue generated by the agents could feel overly formal" and agents were "overly cooperative," accepting suggestions that did not align with their character.

## Common Misconceptions

1. **"The agents are actually conscious or self-aware."** -- No. The paper states (Section 1): these are "computational software agents that simulate believable human behavior." The architecture uses LLM prompting with memory, reflection, and planning -- there is no claim of consciousness. The believability is a surface-level behavioral property, not an internal cognitive one.

2. **"The agents learn or fine-tune over time."** -- No. The LLM weights are frozen. All "learning" is in the memory stream -- new observations, reflections, and plans are added, but the underlying model never updates. The paper explicitly notes (Section 4) that the architecture "extends a large language model" with external memory mechanisms, not by modifying the model itself.

3. **"The Valentine's Day party was scripted."** -- No. The paper states (Section 7.1.2) that only "one agent is initialized with an intent to organize a Valentine's Day party" and "Maria's character description mentions that she has a crush on Klaus." Everything else -- "spreading the word, decorating, asking someone out on a date to the party" -- emerged from the agent architecture without further user intervention.

4. **"You need GPT-4 for this to work."** -- The paper used gpt-3.5-turbo (ChatGPT), not GPT-4. Section 4 notes: "Our current implementation utilizes the gpt3.5-turbo version of ChatGPT... As of writing, however, GPT-4's API was invitation-only, so our agents use ChatGPT."
