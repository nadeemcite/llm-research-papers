# Code Architecture — Self-Rewarding LM Notebook

## Overview

The notebook implements the self-rewarding language model pipeline from scratch in PyTorch on a tiny character-level GRU language model (179,358 parameters). It runs 2 iterations of self-reward DPO on 400 synthetic instruction pairs, where the model generates responses, judges them via a structural-quality proxy, and trains with DPO + SFT. The key result is that both generation quality and judge accuracy improve across iterations.

## Section-by-Section Breakdown

### 1. Imports & Configuration

Sets random seeds and defines the key constants (copy the values from the code cell, never from memory):
- `EPOCHS = 40`, `BATCH_SIZE = 32`, `LR = 5e-4`
- `BETA = 0.5` — DPO temperature (paper uses 0.1)
- `SFT_WEIGHT = 0.1` — auxiliary NLL loss weight (paper uses 1.0)
- `EMBED_DIM = 64`, `HIDDEN_DIM = 128`, `N_LAYERS = 2`
- `SEQ_LEN = 20`, `PROMPT_LEN = 5`, `VOCAB_SIZE = 30`
- `N_TRAIN = 400`, `N_TEST = 100`, `N_ITERATIONS = 2`, `SFT_EPOCHS = 30`
- `N_GENERATIONS = 4`, `GEN_TEMPERATURE = 0.8`

### 2. Synthetic Instruction Data

**Function: `generate_instruction_data`** — generates (prompt, pattern_type) pairs. Each prompt is a random sequence of 5 tokens; pattern type is 0 (repeating) or 1 (low-entropy).

**Function: `generate_response`** — generates a response for a given prompt and pattern type. Quality='good' follows the pattern (alternating two chars for type 0, or using only 3 distinct chars for type 1); quality='bad' produces random noise.

### 3. Character-Level GRU Language Model

**Class: `TinyLM`** (179,358 parameters)
- `nn.Embedding(30, 64)` → `nn.GRU(64, 128, num_layers=2, batch_first=True)` → `nn.Linear(128, 30)`
- Takes (batch, seq_len) token IDs, returns (batch, seq_len, vocab) logits.

**Function: `compute_logps`** — computes total log-probability of a completion given a prompt. Concatenates prompt + completion, runs the model, extracts log-softmax of completion tokens at the correct positions (logits at position `prompt_len-1+i` predict completion token `i`). Returns (batch,) total log-probabilities.

**Data flow:**
```
Input: (batch, prompt_len + seq_len) LongTensor
  -> Embedding -> (batch, seq, 64)
  -> GRU -> (batch, seq, 128)
  -> Linear -> (batch, seq, 30)
  -> log_softmax + gather -> (batch,) total log-prob
```

### 4. DPO + SFT Loss

**Function: `dpo_sft_loss`** — combined DPO + SFT objective:
- L_DPO = −mean(log σ(β · (log π(y_w) − log π_ref(y_w) − log π(y_l) + log π_ref(y_l)))) — standard DPO loss with frozen reference
- L_SFT = −mean(log π(y_w\|x)) — NLL on chosen response
- Total = L_DPO + SFT_WEIGHT · L_SFT

Returns total loss and metrics dict (dpo_loss, sft_loss, reward_margin, dpo_accuracy).

### 5. LLM-as-a-Judge (Self-Rewarding Mechanism)

**Function: `compute_judge_score`** — proxy for the LLM-as-a-Judge. For pattern type 0 (repeating): score = −transition_count (fewer transitions = better). For type 1 (low-entropy): score = −unique_token_count (fewer unique tokens = better).

**Function: `sample_from_model`** — generates responses by autoregressive sampling from the model. For each of N samples, generates seq_len tokens one at a time using multinomial sampling with the specified temperature. Returns (B × N, seq_len) tensor.

**Function: `create_self_reward_pairs`** — the self-rewarding pipeline: (1) generate N responses per prompt, (2) judge each with `compute_judge_score`, (3) pick best (chosen) and worst (rejected) per prompt. Returns (prompts, chosen, rejected) tensors.

### 6. SFT Warmup

Trains the base model for 30 epochs on known-good responses (ground-truth "good" responses generated by `generate_response`). Uses AdamW with lr=1e-3. This gives the model enough capability to generate meaningful responses for the first self-reward iteration. In the paper, the starting point is Llama 2 70B SFT which already has instruction-following capability.

### 7. Iterative Self-Reward DPO

The core loop. For each iteration:
1. **Generate** self-reward preference pairs using the current model (temperature 0.8, 4 samples per prompt)
2. **Create reference model** (frozen copy of current model)
3. **Create policy model** (copy of current model, will be trained)
4. **Train with DPO + SFT** for 40 epochs with AdamW (lr 5e-4)
5. **Evaluate** three metrics:
   - `evaluate_preference_accuracy`: raw log-prob preference accuracy on ground-truth test pairs
   - `evaluate_generation_quality`: average structural quality score of model-generated responses
   - `evaluate_judge_accuracy`: agreement between model's log-prob ranking and oracle quality ranking

### 8. Results Across Iterations

Four subplots: (1) preference accuracy with baseline reference line, (2) generation quality with baseline, (3) judge accuracy with baseline, (4) DPO loss per iteration.

### 9. Final Evaluation

Prints baseline vs final comparison for all three metrics, plus per-iteration breakdown.

### 10. Baseline vs Self-Reward Comparison

Three bar charts comparing baseline (SFT only) vs final iteration for preference accuracy, generation quality, and judge accuracy.

## Deliberate Simplifications vs Full Paper

| Aspect | Paper | Notebook |
|---|---|---|
| Model | Llama 2 70B | 2-layer GRU, 179,358 parameters |
| Dataset | Real instruction-following prompts | 400 synthetic instruction pairs |
| Judge | LLM-as-a-Judge prompt (1–5 scoring) | Structural-quality proxy (transition/unique-token count) |
| Iterations | 3 (M1, M2, M3) | 2 |
| Training | DPO + SFT (α=1.0), β=0.1 | DPO + SFT (α=0.1), β=0.5 |
| Evaluation | AlpacaEval 2.0, RewardBench, MT-Bench | Preference accuracy, generation quality, judge accuracy on synthetic test set |
