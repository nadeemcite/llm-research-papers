# Textbooks Are All You Need (phi-1)
[![Kaggle](https://kaggle.com/static/images/open-in-kaggle.svg)](https://www.kaggle.com/code/nadymsazad/phi-1-textbooks-are-all-you-need)

- **Paper:** [Textbooks Are All You Need](https://arxiv.org/abs/2306.11644)
- **Authors:** Suriya Gunasekar, Yi Zhang, Jyoti Aneja, Caio César Teodoro Mendes, Allie Del Giorno, Sivakanth Gopi, Mojan Javaheripi, Piero Kauffmann, Gustavo de Rosa, Olli Saarikivi, Adil Salim, Shital Shah, Harkirat Singh Behl, Xin Wang, Sébastien Bubeck, Ronen Eldan, Adam Tauman Kalai, Yin Tat Lee, Yuanzhi Li
- **Lab, year:** Microsoft Research, 2023 (arXiv preprint, June 2023)

## Summary

In June 2023, Microsoft Research introduced phi-1, a 1.3B-parameter Transformer model for code generation that punched far above its weight. While competing models like StarCoder (15.5B parameters, 1T training tokens) and CodeGen-16B (577B tokens) used massive datasets and model sizes, phi-1 was trained on just 7B tokens of carefully curated "textbook quality" data — 6B tokens filtered from The Stack and StackOverflow, plus 1B tokens of synthetic Python textbooks generated by GPT-3.5. Despite being 10x smaller in model size and 100x smaller in dataset size, phi-1 achieved 50.6% pass@1 on HumanEval (a benchmark of 164 Python programming tasks) and 55.5% on MBPP (Mostly Basic Python Programs), surpassing almost all open-source models of the time except GPT-4.

The paper's central insight was that data quality matters more than data quantity. The authors observed that standard code datasets like The Stack contain many snippets that are incomplete, not self-contained, full of boilerplate, or lacking meaningful algorithmic logic — hardly the material a good textbook would teach from. By filtering for "textbook quality" (clear, self-contained, instructive, balanced) and generating synthetic textbooks with GPT-3.5, they showed that high-quality data can dramatically change the shape of scaling laws, allowing small models to match the performance of much larger ones.

This notebook demonstrates the principle at toy scale: it trains two identical small Transformer models (~852K parameters each), one on 500 textbook-quality Python snippets and one on 2000 raw/noisy snippets, and compares code-completion quality. The textbook model achieves 99.7% character accuracy on held-out function completions versus 5.3% for the raw model.

## What Problem Does It Solve

Imagine you are learning to cook. Someone gives you two options: a shelf of 2000 random recipe pages torn from magazines — some half-ripped, some just ingredient lists with no instructions, some for dishes you will never make — or a single well-written cookbook with 500 recipes, each clear, complete, and teaching a specific technique. Which would make you a better cook? The cookbook, of course. The random pages might contain more words, but most are noise.

That is exactly what phi-1 argues about training code models. The standard datasets (The Stack, StackOverflow) are like the pile of torn magazine pages: huge, but full of incomplete snippets, boilerplate, and code that teaches nothing. The paper shows that a small set of "textbook quality" examples — clear, self-contained, instructive — trains a better model than a massive pile of unfiltered code, just as a good cookbook teaches better than a mountain of random recipes.

## Core Idea

- **Textbook quality data:** The key ingredient is not more data but better data. "Textbook quality" means clear, self-contained, instructive, and balanced — each example teaches a concept, like a well-written textbook chapter.
- **Synthetic data generation:** The authors used GPT-3.5 to generate synthetic Python textbooks (~1B tokens) and exercises (~180M tokens), carefully prompting for diversity in topics, difficulty, and style to avoid repetition.
- **Filtering existing data:** A transformer-based classifier filtered 6B tokens from The Stack and StackOverflow, keeping only snippets with high "educational value" — self-contained, with meaningful logic, well-documented.
- **Finetuning on exercises:** A small (~180M token) CodeExercises dataset finetuned the base model, boosting HumanEval from 29% to 50.6% and unlocking emergent capabilities not seen in the base model.

## Key Method Details

- **Model architecture:** Decoder-only Transformer with FlashAttention, 24 layers, hidden dimension 2048, MLP inner dimension 8192, 32 attention heads of dimension 64, rotary position embeddings (rotary dimension 32). MHA and MLP layers in parallel (following CodeGen). phi-1-small: 20 layers, 1024 hidden, 4096 MLP, 16 heads.
- **Training data:** CodeTextbook (6B filtered code-language + <1B synthetic textbooks = ~7B tokens) for pretraining; CodeExercises (~180M tokens of synthetic Python exercises) for finetuning.
- **Pretraining:** 36,000 steps (checkpoint at 24,000), effective batch size 1024, max LR 1e-3 with 750-step warmup, weight decay 0.1, AdamW, fp16, sequence length 2048, 8 A100 GPUs, ~4 days (770 GPU hours).
- **Finetuning:** 6,000 steps, effective batch size 256, max LR 1e-4 with 50-step warmup, weight decay 0.01, ~7 additional hours.
- **Results:** phi-1: 50.6% HumanEval pass@1, 55.5% MBPP pass@1. phi-1-base (before finetuning): 29% HumanEval. phi-1-small (350M): 45% HumanEval.
- **Data contamination check:** N-gram overlap analysis found only 4 false-positive 13-gram overlaps with HumanEval. Aggressive data pruning (removing 40%+ of CodeExercises) still yielded 45–50.6% HumanEval, confirming performance is not from contamination.

### Simplifications in This Notebook

- 4-layer character-level Transformer (~852K parameters) instead of 24-layer 1.3B phi-1
- 500 synthetic textbook-quality Python snippets + 2000 raw/noisy snippets, instead of 7B tokens from The Stack + GPT-3.5 textbooks
- Character-level tokenizer instead of the CodeGen-350M tokenizer
- 30 epochs with AdamW (lr=1e-3, batch 64) instead of 36,000 steps with linear-warmup-linear-decay on 8 A100s
- Evaluation via character accuracy and exact match on 51 held-out function-completion prompts, not HumanEval pass@1
- No FlashAttention, no rotary position embeddings (learned positional embeddings instead), no parallel MHA/MLP

### What the Notebook Result Shows

On 51 held-out function-completion prompts, both models score 0% exact match (the character-level model at this scale generates correct first lines but then continues with noisy completions rather than stopping). However, the textbook model achieves 99.7% character accuracy — it almost always generates the correct return statement as the first line — versus 5.3% for the raw model, a dramatic 94 percentage-point gap. The textbook model produces 1/51 syntactically valid completions versus 0/51 for the raw model. Training the textbook model took 18 seconds on a T4 GPU; the raw model took 64 seconds (4x more data) but learned almost nothing useful for code completion.

This mirrors phi-1's finding that textbook-quality data is dramatically more efficient than raw data for teaching code generation. These numbers are not comparable to the paper's 50.6% HumanEval pass@1 — they demonstrate the principle at toy scale with an 852K-parameter character-level model.

## Influence

phi-1 directly inspired a line of "small models, high-quality data" research at Microsoft and beyond. The follow-up phi-1.5 (Li et al., 2023) extended the approach to general language tasks, and phi-2 (Gunasekar et al., 2023) and phi-3 (Microsoft, 2024) scaled the philosophy further. The paper's emphasis on synthetic data quality influenced the broader open-source community's data curation practices for training efficient small models. The TinyStories paper (Eldan and Li, 2023), which phi-1 built upon, established the foundational idea that data quality can reshape scaling laws. About 138 citations ([OpenAlex](https://openalex.org/W4381586770), checked November 2026).
