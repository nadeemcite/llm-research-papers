# Code Architecture — TinyStories Notebook

## Overview

This notebook implements a simplified TinyStories experiment: a 4-layer decoder-only Transformer (8,312,320 parameters) is trained on 10,000 stories from the TinyStories validation split for 3 epochs on a Kaggle T4 GPU. Training loss decreases from 5.98 to 4.33, and the model achieves a test perplexity of 56.75 on 200 held-out stories. The model learns meaningful word prediction but produces short completions at this training scale.

## Section-by-Section Breakdown

### 1. Imports & Configuration

Sets random seeds and defines the key constants (values copied from the code cell):
- `VOCAB_SIZE = 10000` — top-10K word vocabulary (paper uses top-10K GPT-Neo tokens)
- `D_MODEL = 256` — embedding dimension (paper uses 256 for sub-10M models)
- `N_LAYERS = 4`, `N_HEADS = 8`, `BLOCK_SIZE = 128`
- `BATCH_SIZE = 64`, `EPOCHS = 3`, `LR = 3e-4`
- `N_STORIES = 10000` — number of stories from the validation split
- `SEED = 42`

### 2. Data

Downloads the TinyStories validation split (~22,000 stories) from Hugging Face in parquet format. Each story is a short text (2-3 paragraphs) generated by GPT-3.5/GPT-4 using vocabulary a 3-4-year-old understands. The parquet file is read with `pyarrow.parquet` and stories are extracted as a list of strings.

### 3. Word-Level Tokenizer

**Class: `WordTokenizer`** — Maps the top 10,000 most frequent words to token IDs. Special tokens: `<pad>` (id 0), `EndOfText` (id 1), `<unk>` (id 2). Vocabulary is built by counting word frequencies across the training stories with `collections.Counter` and keeping the top 9,997 words plus 3 special tokens. Encodes text to integer lists (appending EOS), decodes back to strings (stopping at EOS, skipping PAD).

### 4. Dataset & DataLoader

**Class: `TinyStoriesDataset`** — Creates fixed-length sequences of `BLOCK_SIZE + 1` tokens from stories. Short stories (shorter than block_size) are padded to the full length. Longer stories are split into overlapping sliding windows. Each `__getitem__` returns input (tokens 0..block_size-1) and target (tokens 1..block_size) tensors for next-token prediction.

**Data flow:**
```
Story text -> tokenize -> list of token IDs
  -> pad or window into (block_size + 1) chunks
  -> __getitem__ returns x: (block_size,), y: (block_size,)
  -> DataLoader batches -> x: (batch, block_size), y: (batch, block_size)
```

Result: 10,821 training sequences, 169 batches of size 64.

### 5. Model

**Class: `TinyStoryLM`** (8,312,320 parameters)
- Token embedding: `nn.Embedding(10000, 256)`
- Positional embedding: `nn.Embedding(128, 256)` (learned, not rotary)
- 4 × `TransformerBlock` (d_model=256, nhead=8, dim_feedforward=1024, dropout=0.1, GELU)
- LayerNorm + linear LM head (no bias)

**Class: `TransformerBlock`** — Pre-norm architecture with residual connections. Each block has LayerNorm → MultiheadAttention (with causal mask) → residual, then LayerNorm → MLP (Linear→GELU→Linear→Dropout) → residual. Causal masking uses an upper-triangular `-inf` mask.

**Data flow:**
```
Input: (batch, 128)  # token IDs
  -> tok_emb + pos_emb -> (batch, 128, 256)
  -> 4x TransformerBlock with causal mask -> (batch, 128, 256)
  -> ln_f -> (batch, 128, 256)
  -> head -> (batch, 128, 10000)  # logits over vocab
```

Differences from the paper: learned positional embeddings instead of GPT-Neo's rotary, word-level tokenizer instead of subword, 128-token block instead of 256/512, `nn.MultiheadAttention` instead of custom attention.

### 6. Loss Function

Standard next-token cross-entropy with `ignore_index=pad_id`. The model predicts the next word given all previous words. This is the same autoregressive language modeling objective as GPT-Neo and the paper.

### 7. Training Loop

- Optimizer: AdamW (lr=3e-4, weight_decay=0.1)
- Gradient clipping: max norm 1.0
- 3 epochs, 169 batches per epoch, batch size 64
- Epoch 1: Loss 5.9826 (21.7s)
- Epoch 2: Loss 4.7105 (40.4s)
- Epoch 3: Loss 4.3312 (61.6s total)

### 8. Results and Plots

- **Training curve:** Line plot showing loss decreasing from 5.98 to 4.33 over 3 epochs
- **Story generation:** Three prompts with temperature 0.8, top_k 40 — the model produces short completions
- **Evaluation:** Test loss 4.0387, perplexity 56.75 on 200 held-out stories
- **Coherence check:** Four temperatures (0.0, 0.5, 0.8, 1.0) showing the model's generation behavior

**Function: `generate`** — Autoregressive generation with greedy (temperature=0, argmax) or sampling (temperature>0, top-k filtering) modes. Generates up to `max_new_tokens` new tokens, stopping at EOS.

## Key Functions

| Function / Class | Purpose |
|---|---|
| `WordTokenizer` | Word-level tokenizer with 10K vocabulary and special tokens |
| `TinyStoriesDataset` | Creates fixed-length training sequences from story texts |
| `TransformerBlock` | Single transformer layer (attention + MLP with residuals) |
| `TinyStoryLM` | Full decoder-only Transformer model (~8.3M params) |
| `generate` | Autoregressive text generation with temperature and top-k sampling |

## Deliberate Simplifications vs Full Paper

| Aspect | Paper | Notebook |
|---|---|---|
| Model size | 1M-80M parameters, GPT-Neo architecture | 8.3M parameters, standard Transformer |
| Tokenizer | GPT-Neo subword, top 10K tokens | Word-level, top 10K words |
| Training data | Full TinyStories (~2.7B tokens) | 10K stories from validation split |
| Block size | 256 window, 512 context | 128 |
| Training | Up to 30 hours on V100 | 3 epochs, ~60s on T4 |
| Evaluation | GPT-4 grading (grammar, creativity, consistency) | Perplexity and qualitative samples |
| Position embeddings | Rotary (via GPT-Neo) | Learned |
